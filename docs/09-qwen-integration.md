具体文件链接位于运行索引。选出的代表性记录用于展示观察到的行为，不代表同一版本和模式的完整成功率。原始失败均保留。上述核查由 AI 根据原文与 Trace 完成，候选人仍需亲自验证。

真实 Trace 展示了不同工具观察后的行动：正常资料→读取后回答；冲突资料→读取双方、补查后追问；工具错误→重试后报告未完成。这些动作来自真实模型，不是 Mock 播放器。汇总字段 `react_proven=false` 是评估器不自动作 ReAct 结论的占位值，需通过 Trace 审查，不能代替证据本身。

## 发现的问题与改进

1. 初次沙箱网络连接失败，按权限机制重跑后连通；失败运行保留。
2. 模型直接引用检索摘要，或读取后遗漏正文引用标记。校验拒绝，并反馈被拒绝行动、可用证据和具体修复要求。
3. 冲突时跳过补查，或把版本日期误认为生效日期。加入模型自报冲突后的查证完整性检查，要求缺口涉及制度适用依据，并明确版本日期不能自动决定优先级。
4. 读取错误被解释成资料不存在。未恢复的读取失败阻止 unanswerable，模型需恢复或返回未完成。
5. 硬性文档多样性挤掉 D06 的关键片段。改为相关性与软多样性平衡，同一查询保留规则和替代依据，同时保留 D01/D02；此为单查询实验，不是总体召回保证。
6. 历史仅作为嵌套 JSON 时有指代失败。增加实际 user/assistant 角色传递；仍要求制度事实重新取证。
7. 思考模式与非思考 JSON 模式表现不同。非思考在上下文和替代引用的小规模对照中更好，但整批重跑仍失败，不能认定它普遍更优。本地配置未被实验覆盖。
8. 泛化的字段错误反馈不足，补充缺失和多余字段名称；再次验证仍有反复修复，不能宣称该问题已经解决。

## 必须报告的失败与限制

非思考 `acceptance` 整批自动状态/文档 ID 检查为 **9/13**：A02、A03 未完成，B04 未追问范围，B11 修复耗尽额度。随后 `protocol-repair` 为 **0/3**，说明详细字段反馈没有单独解决停止和修复稳定性。`final` 批次自动检查 8/9 也不能解释为语义 8/9，其中冲突回答仍混淆版本日期，另有修正后的单例可对照。

自动检查只覆盖状态、必需文档 ID 和部分查证流程，不完全判断原文是否支持整个结论。规则检查也不能代替模型业务判断，尤其是范围、生效条件、替代关系和自然语言缺口。

下一步应固定提示版本、模型模式和数据集重复评估，改善格式修复、无关检索终止和上下文稳定性，逐项核对语义。当前有可运行真实链路及动态路径证据，尚未达到全部稳定验收通过的状态。
