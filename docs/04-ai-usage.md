# AI 辅助与实际贡献记录

本记录截至第六阶段开发，不代表候选人的独立验证已完成。

## AI 辅助范围

- 根据题目与用户提供的旧需求稿起草、合并需求，定义接口和验收矩阵。
- 生成合成制度、产品 FAQ、独立资料快照和测试输入。
- 编写知识库、检索、工具执行、模型适配器、Agent 循环、引用校验、CLI、评估入口和测试。
- 执行本地测试与 Mock 运行，检查实际输出，修复评估入口路径错误。
- 使用 OpenAI Docs 技能核对 [官方接口格式](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)，随后查阅阿里云官方 Qwen、流式调用与结构化输出文档，接入用户指定的 Qwen 模型。
- 实际执行 Qwen 核心和边界案例，保留失败及重跑；根据失败改进校验反馈、历史消息传递、冲突查证、工具错误处理与检索排序。
- 整理 README、实现说明、评估结果和阶段记录。
- 第四阶段编写原生函数调用、问题消歧、进展限制、适用条件及答案复核，增加证据依赖与日期来源校验；由 AI 为合成 D06 标注配套引用关系，未改变制度正文。
- 执行多批真实回归并保留失败、中断记录；AI 逐条检查答案时发现自动检查遗漏的日历推算，保存问题记录后修复并重新执行固定版本两轮评估。
- 第五阶段增加五类请求、落盘证据复核脚本及受控边界实验，执行扩大后的回归。根据实际失败关闭真实模式的独立指代分类，隔离事实复核中的助手旧答案，并添加通用数值差异风险检查；没有按用例编号写入业务答案，也未修改制度正文来匹配输出。
- 第五阶段的运行、失败诊断、AI 答案审读与文档均由 AI 执行；自动检查遗漏的追问对象及引用关联问题另行记录，不将模型复核或 AI 审读称为候选人独立验证。
- 第六阶段由AI编写交付打包和解压验证脚本、8项交付测试、交卷说明与指南，完成无密钥副本复现，并修正保存路径的跨系统分隔符处理。业务引擎与历史模型输出不变，未发起新的真实模型效果评估。

## 用户已明确参与的内容

用户选择第三题，提供考核要求和旧需求文档，要求先分析再开发，要求合并文档并检查一致性，分阶段授权实施并强调避免已识别风险。用户指定 `qwen-flash`、北京接口地址与思考/流式示例，并在本地配置密钥。第六阶段用户提供目标GitHub仓库及本仓库提交作者信息。用户旧稿的具体创作过程不在本次会话中推断。

尚未记录候选人独立编写代码、修改算法或亲自运行测试的贡献；后续应由候选人据实补充，不能将 AI 生成或执行的工作写成个人手写、个人实测。

## 验证边界

当前112项本地测试、Mock、受控边界实验、解压复现及各阶段真实Qwen运行均由AI执行。模型效果仍以[第五阶段报告](11-effect-evaluation.md)为准，保留自动失败与AI审读问题；第六阶段只验证交付复现，不增加模型正确率结论。密钥仅保留本地`.env`，不进入交付包或Git暂存。Git发布及最终SHA由实际执行结果核对；提交作者信息不证明候选人独立编码或验证。
