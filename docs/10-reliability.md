## 具体改进

1. **结构化行动。** 非思考 Qwen 使用原生 Function Calling，保留调用 ID 和真实工具消息；行动请求非流式读取完整参数。`finish` 只序列化结果，不新增业务工具。缺少调用时反馈，必要时下一次仅约束结束结构，仍由模型选择终态和内容。
2. **上下文与适用条件。** 模型先根据历史补全当前问题或追问，不能在消歧阶段回答业务事实。成功答案前分别核验适用条件和当前证据支持，均计模型预算；不把早先被拒绝答案作为复核事实。
3. **有限进展。** 不重复执行已成功读取的片段；连续两次搜索无新候选后限制继续空转；同片段两次失败后限制相同重试，保留读取其他候选或结束的选择。三次相同协议错误或总预算耗尽明确未完成，不按用例固定输出。
4. **证据约束。** 引文必须来自本次成功读取的当前快照，原文、日期、ID 逐项校验。未恢复工具错误不能隐藏为资料不足或正常追问；声明冲突需双方原文与后续补查。D06 的通用 `citation_dependencies` 标注要求期限与替代原文配套，加载时检查无效引用和环路；模型仍需决定读取并逐字引用，不由程序补证据。
5. **检索与日期来源。** 过滤泛词并删除“多少天等于期限”的错误归一化，避免育儿假仅靠泛词命中报销。实际单查询过滤前后保存在 [检索对照](../examples/stage4/retrieval-filter-comparison.json)，不作整体精度结论。回答新增的中文或 ISO 日期须出自用户条件或引文/版本元数据，不擅自日历推算。
6. **可追溯评估。** 独立检查实际快照、原文观察、引用、有限业务事实、预算和故障反馈，不向模型传预期断言。支持重复次数，完成一条立即原子写汇总，避免中断丢失已经完成的记录；不支持并发进程共同写同一汇总文件。

## 失败与修复证据

开发批次全部保留，计数见运行索引。早期 `pilot` 检查较弱，不能与最终通过数直接比较；`regression` 中途停止，未执行项不计通过。后续遇到复核反复纠缠旧错误、过度拒绝合理追问、缺少替代依据、范围缺失却直接回答等问题，分别以复核输入隔离、只复核成功答案、证据依赖和条件检查处理。

`release-validation` 曾自动 26/26，但 AI 阅读发现 B03 两次把“15 天”转换成未请求且缺乏计日依据的具体日期，问题保存在 [复核记录](../examples/stage4/release-validation/manual-review.json)。没有修改历史输出；补充日期来源校验与回归后，重新运行 `verified-release`，作为本报告最终证据。这也说明自动检查本身需要迭代。

## 限制及后续

- 两次重复、小规模合成资料和有限表达不能代表真实企业知识库；qwen-flash 服务行为也可能变化。
- 日期来源和原文子串不保证完整语义蕴含；模型复核仍可能漏判或误拒绝，证据依赖需要文档作者审查维护。
- B08 故障恢复仍不足。保守校验也可能因无关片段读取失败而阻止合理结束，后续需区分核心证据失败与无关失败。
- 中文词法检索和泛词过滤可能漏召回，需独立陌生查询、长文档与更多冲突集验证；未引入向量库。
- 本地超时丢弃结果不保证远端生成取消；当前不是生产级运行时。
- 本阶段实现、执行和阅读由 AI 完成；候选人需独立核对、补充个人理解与实际用时，之后提交 GitHub URL 和最终 SHA。
