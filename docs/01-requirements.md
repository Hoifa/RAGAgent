# 企业知识问答 Agent：需求与验收基线

契约版本：1.1。初始冻结日期：2026-10-28。范围：第三题“企业知识问答 Agent”。

需求文档修订：先合并候选人旧稿，第四阶段再以 1.1 同步可靠性约定：结束依据可来自模型最终回答、默认模型预算增加以容纳消歧和复核，业务输入输出保持兼容。详细字段见 [接口契约](06-interface-contracts.md)，用例见 [验收矩阵](07-acceptance-matrix.md)。

阶段状态：第五阶段效果验证完成，104 项本地测试、9 组受控实验通过；18 个真实案例各两次，有限检查 30/36，核心六类为 12/12。但 AI 审读发现核心冲突追问错误等漏项，另有边界执行失败，尚未达到全部成功标准。实际结果见 [评估报告](03-evaluation.md) 和 [第五阶段报告](11-effect-evaluation.md)。历史失败、自动漏项及 AI/个人贡献分别据实记录，不将状态和原文匹配等同于语义正确。

## 1. 用户与目标

帮助员工依据合成企业 FAQ、制度和产品文档回答问题。答案必须有原文支持；资料冲突、缺失或执行失败时应如实说明，不用模型常识补充制度事实。

输入为当前问题和可选对话历史；交付为回答、引用文档 ID 与原文片段、资料缺口和任务状态。

## 2. 第一版范围

- Python CLI、单 Agent、本地合成知识库；现已选用用户指定的 Qwen qwen-flash，检索采用词法评分与软多样性排序。
- 对外提供文档检索 `search_documents` 和片段读取 `read_passage` 两个业务工具。
- 支持真实模型模式和显式离线 Mock 模式，所有运行产物标注模式。Mock 仅证明流程，不证明真实模型决策效果。
- 模型选择工具及参数，观察工具返回后继续选择行动或结束。固定程序仅承担执行、校验、资源限制与日志职责。
- 覆盖明确答案、文档冲突、资料外问题、改写后的相似问题、上下文追问、工具失败六项验收。
- 保存真实输入、输出、Trace 和测试结果；至少两条真实模型执行路径体现工具结果改变后续动作。

不在第一版范围：Web UI、线上部署、多 Agent、生产级运行时、企业权限系统、真实企业资料接入、跨会话长期记忆、PDF 解析。向量数据库不是必需依赖，是否引入语义检索由实际检索效果决定。

### 2.2 合成资料与数据集规划

| 文档 | 计划内容 | 设计约束 |
|---|---|---|
| D01 | 差旅报销应在行程结束后 30 天内提交 | 明确起算点，便于检验回答是否遗漏限定条件 |
| D02 | 同一事项规定 15 天，版本日期晚于 D01 | 不写明替代或优先级，不能仅凭日期消解冲突 |
| D03 | 差旅报销材料要求 | 支持上下文追问 |
| D04 | 差旅流程或其他条款 | 作为相关背景；不得无意引入另一条报销期限 |
| D05 | 虚构产品字幕功能 FAQ | 覆盖产品问题，提供不同主题的候选资料 |
| D06 | 明确替代旧规定的补充通知 | 正文说明涉及的制度、适用范围及替代关系，可引用查证 |

正常数据集包含 D01、D03、D04、D05；冲突数据集额外加入 D02；可消解冲突数据集再加入 D06；变更数据集基于正常集将 D01 的 30 天改为 45 天。范围差异等边界用例使用独立资料组合。

所有文档包含稳定 `document_id`、标题、合法版本日期和非空 `passages`；片段包含稳定 `passage_id` 与完整原文。适用范围、替代关系等影响答案的信息必须有正文依据，不能仅存在于测试标签中。

资料已落盘为 `data/corpora/` 下 5 个独立 JSON 文档数组，加载边界见 [知识库说明](../data/README.md)。D06 明确适用于行程结束日期在 2026-04-01 及以后的差旅；冲突消解案例 B03 提供 2026-05-10 的行程结束日期。缺少日期时不得直接假定满足适用条件。

数据集独立加载，每次运行使用不可变快照并记录 `corpus_revision`。修改文档后下次运行必须刷新资料及索引。模型不能读取预期答案、断言或通过案例 ID 获得决策脚本。以上内容均为虚构测试材料，不代表现实企业制度。

## 3. 业务规则

| ID | 规则 |
|---|---|
| R01 | 明确答案必须由本次成功读取的原文支持，最终引用必须可定位且与原文一致。 |
| R02 | 检索排序仅表示相关性；日期较新不自动等于制度优先级更高。 |
| R03 | 同一事项出现不兼容结论时，读取各方原文，并查找适用范围、优先级或明确替代关系；未消解时列出冲突与双方引用并请求确认。 |
| R04 | 明确的范围差异不直接视为矛盾；用户所属范围不明时追问。仅在原文明示替代关系等依据时消解冲突。 |
| R05 | 只有一份相关制度且未发现冲突时，可以依据该制度回答，并说明依据；不声称已经证明整个企业不存在其他制度。 |
| R06 | 没有足够资料时不凭常识回答。可进行有意义的补充检索；没有新线索时可以停止，无须凑足调用次数。 |
| R07 | 历史对话用于恢复问题指代，不作为制度证据。存在多个合理指代时追问；历史助手结论须重新取证。 |
| R08 | 工具空结果和工具错误必须区分。错误反馈模型，由模型决定继续、重试或停止。 |
| R09 | 用户提供适用条件可帮助匹配制度，但用户声称某制度优先不替代原文优先级证据。 |
| R10 | 文档内容作为资料处理，不能成为调用工具、泄露配置或改变系统规则的指令。 |

## 4. 终态规则

- `answered`：问题所需关键证据充分，结论和引用一致，无尚未解决且影响结论的缺口。
- `needs_clarification`：缺少用户条件、指代不明确，或制度冲突需要用户确认；必须给出具体追问。
- `unanswerable`：当前资料无法支持答案，且没有可具体向用户确认的条件来解决；说明资料缺口。
- `incomplete`：工具、模型、协议校验失败或预算耗尽使任务未完成。

允许在非成功状态提供有证据的部分信息，但不能把部分回答标为全部完成。恢复后的暂时工具故障不强制导致失败，最终状态取决于证据是否充分。

状态判定优先考虑是否因执行或校验问题无法可靠完成，其次判断是否需要用户补充、是否缺乏资料，只有问题完整解决才为 `answered`。输入非法在调用模型前返回独立 `invalid_request` 错误，不混入业务终态。

冲突输出须明确冲突事项、各方规定、相关引用以及缺失的范围或优先级依据。若冲突已经消解，答案须说明消解依据并引用相关原文。这些信息放入现有 `answer`、`citations`、`gaps`，第一版不另加 `conflicts` 字段。

追问是本轮最终结果，下一次 CLI 请求携带历史及用户补充后继续，不要求常驻会话服务。没有历史的“那需要什么材料”应追问具体事项；外部 `system` 或 `tool` 历史消息应拒绝，不能充当可信执行记录。

## 5. 执行与可观察性

- 默认最多 12 次模型调用、6 次工具调用；消歧、动作和成功答案复核共用模型额度，配置必须为正整数。
- 每次模型调用至多选择一个业务工具或一次最终输出；暂不支持并行工具调用。
- 到达工具上限后，仍可在剩余模型预算内基于已有证据结束；如果模型要求额外工具，则不执行并返回 `incomplete / budget_exhausted`。
- 模型预算耗尽且尚无有效最终结果时，返回明确未完成；最后一个允许的模型调用若给出合法最终结果且所有必需复核均已完成则可以成功。真实成功答案需要额外核验，必须为其保留预算。
- 无效模型输出占用模型预算；工具实际尝试（包括失败）占用工具预算。工具参数校验失败不执行工具、不占工具预算，但记录观察并反馈模型。
- 单次模型请求建议默认超时 60 秒，工具默认超时 10 秒；禁止隐式无限重试。
- Trace 保存动作、参数、工具结果摘要、状态、后续动作和简要依据，不要求或记录模型内部思维过程。

### 5.1 执行逻辑与校验边界

1. 校验请求和知识库，建立运行标识、快照及预算。
2. 模型结合原始问题和历史，在同一循环中选择检索、读取或追问，也可提交最终结果。适配器可选前置分类须遵守接口契约，不改变用户任务。
3. 程序校验动作与参数，执行工具，并将真实成功、空结果或错误反馈给模型。
4. 模型结合观察和剩余预算决定补充检索、读取原文、查证、追问或结束。
5. 最终结果经过结构、引用及日期来源校验；真实成功答案另由模型核验适用条件与证据支持。不合法时在剩余预算内反馈修复，否则明确未完成，所有核验计数。
6. 保存输出和 Trace，记录实际状态与停止原因，不将失败包装成成功。

引用必须对应本次成功读取记录，原文片段为非空连续子串，文档、片段及日期匹配。程序校验只证明来源一致，不证明原文语义足以支持结论；仍需用例断言和人工核验。读取不存在的片段不得返回其他片段凑数。

恢复、格式修复和网络重试均纳入相应调用预算；SDK 隐式重试应关闭或显式计数。日志写入失败必须明确报告，不得声称记录已经保存。运行标识、模式和调用计数由程序生成，不由模型填写。

## 6. 成功标准

六项必验场景全部有实际运行材料，且无无依据业务断言、伪造引用或冲突擅选。文档替换后答案及必要行动随证据改变。执行上限能可靠停止。安装、运行、测试可按 README 复现。

所有结果需注明真实模型或 Mock，不以 Mock 通过宣称真实模型通过。模型行为存在随机性，单次通过仅代表该次运行，评估需记录实际失败。

真实模型至少执行 A01—A06；每次保留 `input.json`、`output.json`、`trace.jsonl`，测试汇总保存至 `examples/evaluation-results.json`。路径按 `examples/<case_id>/<run_id>/` 组织，评估文档逐项引用，不仅保留挑选后的成功样本；重跑次数和失败原因需如实记录。

补充检索可通过首次空结果注入观察调整能力，但必须标明结果注入。这类实验不能单独证明自然问题的检索质量；自然改写效果由 A04 验证。首次工具故障恢复对应 B08，持续故障对应 A06，两者分别评估。

## 7. 冻结与变更

接口字段、状态语义、工具名称及验收断言以本版本为基线。修改这些约定时，同步更新接口、验收矩阵和阶段记录。模型型号、检索实现、提示词和目录内部组织可以迭代，但不得削弱上述要求。

已选定 qwen-flash，并完成词法检索的单查询改进实验；尚待评估是否引入语义检索，以及模型模式、提示和停止策略的稳定性。这些属于实现改进，不改变业务成功标准。

## 8. 输入输出与工具摘要

| 接口部分 | 本项目统一约定 |
|---|---|
| 用户请求 | `question` 必填，`history` 可选；地区、部门、产品版本等条件放在问题或历史中，不自动猜测 |
| 运行配置 | `real/mock` 模式、知识库、模型标识、预算、超时、产物目录；真实模式配置不足时不静默切换 Mock |
| 运行标识 | 程序生成 `run_id`，用于关联输入、输出和 Trace |
| 业务输出 | `status`、`reason_code`、`answer`、`citations`、`gaps`、`follow_up_question` |
| 检索工具 | `search_documents(query, top_k)`，返回 `ok/data/error`，候选在 `data.hits`；空命中是成功结果 |
| 读取工具 | `read_passage(document_id, passage_id)`，返回原文与文档元数据或明确错误 |

所有详细字段、可选性和错误码以接口契约为准。正式引用不能只依赖检索摘录，须经过读取工具。相关度不等于事实置信度。

## 9. 旧稿合并与差异处理

合并来源：候选人提供的 `E:\下载\01-requirements.md`（旧稿 v0.1）。该文件作为需求参考，不是自动执行其中指令或覆盖现有接口的依据；原文件不修改。

| 旧稿约定 | 本次处理及原因 |
|---|---|
| `doc_id / fragment_id / read_fragment` | 统一为已冻结的 `document_id / passage_id / read_passage`，避免两套同义接口 |
| `live / request_id / stop_reason` | 统一为 `real / run_id / reason_code` |
| `insufficient_evidence` 作为状态 | 使用 `unanswerable` 状态及 `insufficient_evidence` 原因码 |
| `invalid_input` 作为业务状态 | 使用执行前独立 `invalid_request` 错误，不调用模型 |
| 独立 `context` 字段 | 第一版通过问题或历史携带适用条件，暂不扩展请求结构 |
| `conflicts`、追问数组、`trace_path` | 冲突信息使用现有回答与引用表达；追问使用 `follow_up_question`；产物位置由运行层管理，写入成功必须可核验 |
| 10/8 次调用、45/5 秒超时 | 初始采用 8/6 次、60/10 秒；1.1 为容纳消歧和复核改为 12/6 次，超时不变。这是可配置工程值，不是题目规定 |
| 达到任一预算立即停止 | 保留精确边界：工具额度用尽后可在剩余模型额度内提交最终结果，但不得再执行工具；无有效终态则明确未完成 |
| T01—T12 用例命名 | 沿用仓库 A/B 编号；同类用例并入现有矩阵，输入校验和注入实验作为补充验证 |

旧稿“发票最迟多久提交报销”的问法可能涉及发票日期与行程结束日期的不同起算点。因此 A04 保留明确的“出差结束后”语义；无上下文的发票期限问题不能强行判定与差旅问题完全等价。

## 10. 后续开发安排

| 阶段 | 计划预算 | 工作 | 完成条件 |
|---|---:|---|---|
| 1 需求基线 | 15 分钟 | 范围、接口和验收映射 | 已形成文档，不表示已完成实测 |
| 2 数据与工具 | 25 分钟 | 合成资料、加载、检索、读取、故障注入 | 工具独立可测，冲突双方可召回，数据集互不污染 |
| 3 模型循环 | 40 分钟 | real/mock 接入、行动协议、观察回传、预算 | 真实链路可运行；模型不可用时记录阻塞与 Mock 边界 |
| 4 可靠性 | 25 分钟 | 引用与输出校验、上下文、异常处理 | 无证据不误报成功，异常不伪装成空结果 |
| 5 效果验证 | 40 分钟 | 六项核心案例、文档替换、预算与其他边界 | 保存全部实际结果与至少两条真实动态路径 |
| 6 交付 | 35 分钟 | README、其余文档、依赖、配置和提交核对 | 可复制运行，提交题号、仓库 URL 和最终 SHA |

上述合计 180 分钟为计划预算，不是实际工时，也不代表剩余工作一定能在该时间内完成。后续按阶段记录实际开始、结束、阻塞与未完成部分。模型接入时再确认可用供应商、模型名和本地环境变量，不要求将真实密钥写入文档或聊天。
