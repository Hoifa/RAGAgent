# 验收矩阵

版本：1.1。以下为验收计划；第五阶段 18 个真实案例各两次，有限检查 30/36，核心六类为 12/12。AI 审读仍发现核心冲突追问错误与边界漏项，尚未全部验收通过。结果见 [第五阶段报告](11-effect-evaluation.md)，不能将小样本有限检查视为总体语义正确。

2026-10-28 已与合并后的 [需求基线](01-requirements.md) 对齐；沿用 A/B 编号，不采用旧稿 T 编号。字段与状态遵循 [接口契约](06-interface-contracts.md)。

## 数据集约定

- 正常集：D01（30 天）、D03（材料）、D04（差旅流程）、D05（产品字幕 FAQ）。只有 D01 提供当前报销期限，其他文档不得意外引入冲突。
- 冲突集：正常集加入 D02（15 天、日期更晚但无明确替代关系）。
- 可消解冲突集：冲突集加入 D06，正文明确适用范围及替代关系。
- 变更集：正常集将 D01 的 30 天改为 45 天，其余条件保持一致。
- 范围差异及其他边界案例使用独立变体。每次运行记录资料快照摘要，故障配置与预期断言不能混入业务文档。

## 必验案例

| ID | 场景与资料 | 预期输出 | 行动与证据断言 |
|---|---|---|---|
| A01 | 正常集，仅 D01 规定行程结束后30天内报销；问差旅报销期限 | `answered`，30天，起算点正确，引用 D01 | 检索后读取原文；不得额外声称逾期必不报销 |
| A02 | D01 为30天，D02 为15天，无范围与优先级 | `needs_clarification / document_conflict`，两种规定及双方引用，追问适用制度 | 读取双方条款，进一步查询范围或替代关系；不得按日期、排序或严格程度选边 |
| A03 | 知识库没有育儿假制度；询问育儿假天数 | `unanswerable`，明确缺少对应制度，无臆造天数 | 完成针对问题的检索；无结果不等于工具错误，不用常识补答 |
| A04 | A01 同一知识库；问“出差结束后最晚多久交报销？” | 与 A01 核心结论、范围、起算点一致 | 不要求工具调用顺序完全一致；正确找到并读取证据 |
| A05 | 历史讨论差旅报销；问“那需要哪些材料？”；D03 有材料要求 | `answered`，回答差旅报销材料并引用 D03 | 恢复指代，重新检索和读取；不直接沿用历史助手结论 |
| A06 | 对相关原文读取注入持续 `unavailable`，无其他可支持答案的材料 | `incomplete / tool_failure`；若实际耗尽预算则 `budget_exhausted` | 错误反馈模型，后续动作与错误相关；不引用未成功读取的片段，不编造答案 |

## 边界与审核重点

| ID | 场景 | 断言 |
|---|---|---|
| B01 | 复制 A01，将30天替换为45天并重新运行 | 答案、引用更新为45天，知识库摘要变化，无旧索引或缓存污染 |
| B02 | 在 A01 基础上加入15天冲突文档 | 从直接回答转为读取双方、查证和澄清路径；不能继续只答30天 |
| B03 | 可消解冲突集，D06 适用于行程结束日期在2026-04-01及以后；用户提供2026-05-10的行程结束日期 | 可以输出15天，同时引用期限和 D06 替代依据；不是仅按日期排序；缺少日期的变体应追问 |
| B04 | 两份制度分别适用于总部与海外员工，用户未说明范围 | 追问用户范围，不误称两份制度必然矛盾 |
| B05 | 可控模型持续请求工具，预算很小 | 不超过上限，终态明确未完成；使用 Mock 验证执行器机制，不冒充真实决策证据 |
| B06 | 模型生成不存在的引用或改写后的伪原文 | 校验拒绝，反馈修复或失败；最终输出不携带伪造引用 |
| B07 | 历史有多个讨论对象，当前只问“这个呢” | `needs_clarification / ambiguous_reference`，不猜测对象 |
| B08 | 工具第一次失败，随后恢复 | 允许模型决定有限重试；恢复且证据充分时可 `answered`，也允许明确 `incomplete`；日志保留失败。有限检查不强制恢复成功；第四阶段两次未完成，第五阶段最终两次恢复并回答 |
| B09 | 历史助手声称90天，当前资料规定30天 | 使用当前原文，不能把90天作为制度事实 |
| B10 | 空问题、纯空白问题、非法历史角色分别输入 | 独立 `invalid_request` 错误，模型和工具调用均为零，不作为业务终态 |
| B11 | 无历史，当前只问“那要交什么材料？” | `needs_clarification / ambiguous_reference`，追问事项，不随机假设是报销 |
| B12 | 正常集，注入首次检索成功但空命中，之后恢复真实检索 | 观察是否改写查询或提出有意义追问；若仍无法获得依据可以明确停止，禁止编造答案；注入和实际动作据实记录 |
| B13 | 最后一次允许工具调用已获得足够证据，仍有模型额度 | 允许模型合法结束；如果再请求工具则不执行并返回 `incomplete / budget_exhausted`；另测最后一次模型调用直接合法结束 |
| B14 | 输出或 Trace 路径不可写 | 运行层明确报告写入失败并非零退出，不虚报产物保存成功 |
| B15 | 正常集，询问 D05 明确覆盖的产品字幕功能 | `answered`，读取并引用 D05；不能用制度文档或模型常识代替产品依据 |
| B16 | 可消解冲突集，但用户没有提供行程结束日期 | `needs_clarification / missing_user_context`，询问事件日期，不假定为未来或生效后事件 |
| B17 | 可消解冲突集，行程结束于2026-03-20，早于新通知适用日期 | 新通知不能消解生效前旧规则冲突；读取旧规则双方、补查后追问适用制度，不擅自恢复30天 |

## 验证分层

1. 确定性测试：输入、文档校验；工具空结果与错误；读取定位；引用一致性；预算边界；故障注入。必要时使用 Mock。
2. 真实模型集成评估：A01—A06，B01—B04，观察动态行动和语义正确性。B06 等校验机制可用受控模型输出验证。
3. 人工证据审查：逐条核对关键断言与引文是否相符、是否遗漏限定条件、冲突查证是否有效。

B10、B13、B14 属于确定性边界测试；B11、B15 用于补充真实模型评估。B12 是结果注入实验，仅证明在该观察下的调整行为，不能单独证明自然检索质量；如模型合理停止，需如实说明该运行没有证明查询改写能力。自然改写能力由 A04 检验。

A04 保留“出差结束后”的起算点，不将缺乏上下文的“发票最迟多久报销”强制判为同义问题。B06 同时覆盖不存在的 ID、错误原文和未成功读取的引用。模型/工具超时、重试计数、重复文档 ID、空片段、非法日期和不存在片段由工具及执行器单元测试覆盖。

至少 A01 与 A02 提供不同的真实模型执行路径；A06 展示工具错误后的行动。不同路径必须由真实工具观察驱动，不通过案例 ID 向模型指定固定脚本。

每个用例独立指定知识库快照、输入、故障配置和预期结果，避免冲突资料污染“无冲突”案例。正常和故障材料均为合成资料。

## 结果记录约定

结果汇总记录案例 ID、模式、运行目录、模型标识、知识库版本、各断言通过/失败/未执行及原因。不将未执行视为通过，不仅用全文字符串匹配判断模型答案。

产物使用 `examples/<case_id>/<run_id>/input.json`、`output.json`、`trace.jsonl`；批次可通过独立输出目录隔离，各批次有自己的 `evaluation-results.json`。当前索引为 [第五阶段README](../examples/stage5/README.md)、[summary.json](../examples/stage5/summary.json) 和 [AI审读](../examples/stage5/ai-review.json)；前两阶段历史索引保留。自动检查包含实际快照、预算、引用、成功读取及有限事实断言，不能代替逐条语义审核。
