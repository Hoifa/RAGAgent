# 实现流程与技术取舍

## 当前架构

Python 3.9 标准库实现，无 Agent 框架、向量数据库或第三方 SDK。CLI 为 `python -m src.kb_agent`。已完成 Qwen 实际接口联调并保留成功、失败与修复后的 Trace，具体结果见评估文档。

| 模块 | 职责 |
|---|---|
| `src/kb_agent/knowledge.py` | 加载并校验独立快照、计算 SHA-256、检索、读取、显式故障注入 |
| `src/kb_agent/models.py` | Chat Completions 兼容 HTTP 请求、行动协议提示、独立的预设 Mock |
| `src/kb_agent/agent.py` | 模型调用→工具执行→观察回传→继续或结束；计数、超时、Trace |
| `src/kb_agent/contracts.py` | 输入、动作、工具参数、终态和引用校验 |
| `src/kb_agent/__main__.py` | CLI、配置、产物保存和退出码 |
| `src/kb_agent/evaluate.py` | 测试侧加载案例、运行和追加汇总；不向模型发送预期答案 |
| `src/kb_agent/prompts.py` | 动作、消歧、适用条件和证据复核的独立提示 |
| `src/kb_agent/native.py` | Qwen 原生函数调用定义、消息关联和最终结构提交 |
| `src/kb_agent/progress.py` | 新候选、已读片段、失败次数等机械进度信号 |
| `src/kb_agent/assessment.py` | 测试侧的事实、原文、预算和故障后行动检查 |
| `src/kb_agent/conflicts.py` | 从实际候选发现同措辞数值差异，阻止未核实双方或无关联依据的直接回答；不选择正确数值 |
| `scripts/audit_evidence.py` | 离线读取落盘证据、复用业务校验，额外检查 Trace 完整性、工具观察重放及同配置对照 |
| `scripts/run_boundary_checks.py` | 保存预算、伪造引用、非法输入与写入失败的受控实验；不作为真实决策证据 |

第四阶段以契约 1.1 取代早期实现细节，见接口契约。Qwen 非思考模式优先采用 [官方 Function Calling](https://help.aliyun.com/zh/model-studio/qwen-function-calling)，以 `auto` 选一个函数；不依赖 Qwen 不保证支持的 `required`。`finish` 只承载最终结构，不是业务工具。动作使用完整非流式参数，其余模型请求保持配置。

当前真实适配器由同一模型动作循环判断指代并选择检索或追问。第五阶段尝试限制前置分类改写，仍发现其对明确问题过早追问，最终默认关闭该阶段；可选适配器分类接口仍保留受控校验。成功答案追加不看候选答案的适用条件核验，以及不看旧错误的事实复核。两类复核只保留用户历史条件，避免助手旧错误干扰；业务循环保留原问题和全部历史。所有调用计入 12 次总预算，业务工具仍限 6 次；合理拒答和澄清保留确定性校验。

结束行动不强制重复 `reason`，没有时用模型最终回答作为可审查说明。连续相同错误、重复读取和无新候选搜索有上限，但运行时不替模型决定业务答案。每轮观察按真实对话顺序回传，不重复嵌套整段请求。

通用 JSON 后端每轮接收请求、历史、动作、工具结果和预算；Qwen 非思考后端则转换为原生调用和 tool 消息，二者统一成同一内部动作。工具由本地执行器调用，程序不按问题或案例 ID 编写答案。被拒绝的输出和具体错误回传模型修正。

兼容接口格式依据 [官方 Chat Completions API 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 核对。后续用户指定 Qwen：默认 `qwen-flash` 和用户提供的北京基础地址，不自动替换地址或模型。

配置读取根目录 `.env`，shell 环境变量优先；Qwen 支持 `DASHSCOPE_API_KEY`，也支持显式 `LLM_API_KEY`。读取过程无插值、无代码执行、无凭据输出。默认开启思考和流式调用，HTTP 顶层发送 `enable_thinking=true`（相当于 SDK 的 `extra_body`）。

SSE 解析只累加 `delta.content`，忽略思考字段和 usage-only 包；要求正常结束标记与 `[DONE]`，拒绝截断、过滤或超长流。依据 [阿里云结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)，Qwen-Flash 思考模式不能依赖 JSON 结构化输出保证格式，因此默认不发送 `response_format`，保持本地严格校验。原生 JSON 校验不会因更换供应商而取消。

运行元数据记录非敏感的端点、流式/思考/JSON 模式及系统提示内容 SHA-256，便于区分配置和提示词迭代；不包含密钥和模型内部思考。

## 检索与证据

中文双字切分、英文/数字词及少量通用表达归一化，采用 BM25 形式的词频/文档频率评分。查询“出差”“最晚”“多久”等映射到相关概念，不包含问题→答案表，也不依赖 D01 等 ID 决定业务结论。

初版排序先取每份文档一个片段。真实 B03 暴露其缺陷：D06 的例外条款入选，但有效期限和替代依据被不相关文档挤掉。现改为逐次选择 `相关性评分 / (1 + 0.5 × 已选同文档片段数)`，以软惩罚平衡多样性和相关性，不按数字或观点一致性去重。`top_k` 默认 5，允许 1—10。

对同一真实查询“差旅报销期限”，D06/P01、P02 的前五名召回由 0/2 改为 2/2，D01/D02 同时保留。原始与改进结果见 `examples/qwen-validation/retrieval-comparison.json`。这是单查询改进证据，不是普遍召回保证；文档超过上限、陌生表达仍可能漏召回。

检索仅返回候选摘录；正式引用必须从 `read_passage` 成功返回的完整片段登记。每次运行独立加载知识库，不共享跨运行缓存；内容摘要基于规范化文档内容，文档 ID 和版本日期不变也能检测正文修改。返回数据复制，调用方不能通过修改结果污染快照。

第四阶段补充泛词过滤，移除“多少天→截止期限”这一不成立的语义等价；否则育儿假问题可能只靠“规定”等词命中报销条款。

配套引文关系由资料作者显式声明，读取时返回位置，模型再决定读取并引用。校验器只要求引用依赖闭合，不决定新旧制度孰优、不选择期限值。D06 的期限条款依赖替代依据，避免模型只引用数字而跳过优先级证据；正文没有为测试改写。依赖图加载时检查缺失节点和环。

## 动态决策与可信边界

真实模式的补查、读取顺序、冲突查证、追问和终止由模型选择。日期较新不自动优先；D06 的替代关系必须有原文依据且适用日期匹配。历史仅用于指代，不能提供制度证据。提示词明确文档是资料而非指令，但提示词不能保证抵御所有恶意资料。

Mock 是 `ScriptedModel`，按测试脚本逐条播放动作，不根据工具观察推理；它也会经过真实的工具、引用校验和执行上限，但不能证明 ReAct。根目录 examples 下早期 A01—A06 记录为 Mock，第四阶段真实记录独立存于 `examples/stage4/verified-release/`，不可混用。

引用校验拒绝未成功读取的片段、错误日期、伪造原文、重复或悬空引用。模型自报 `document_conflict` 时，程序检查是否引用双方并在读取后补充查证；同时要求资料缺口明确涉及适用规则，而不是只问行程日期。程序不判断哪份制度正确、不代替模型选动作。

第五阶段还发现模型不声明冲突、只引用其中一方的关键缺陷。现从真实检索摘录和读取观察提取“文字相同、数值不同”的跨文档候选风险，加入运行上下文。`answered` 必须先读取风险双方，并引用明确关联双方文档 ID 的适用/替代原文；无此依据时反馈模型继续查证或澄清，不替它选答案。该机械约束偏保守，只覆盖同措辞数值差异，不能检测改写后的所有冲突，也可能误拦措辞相同但范围另有说明的资料。摘录仅作为风险信号，不能据此生成正式引文。

对 `unanswerable` 和 `needs_clarification` 检查是否仍有未恢复的原文读取失败或最后一次检索失败，避免把执行问题误报成资料缺失或转交用户；模型仍可选择恢复或返回未完成。这是偏保守的完整性检查，无法自动判断失败读取是否与问题无关。

上述校验只能验证来源与有限流程约束，不能证明语义蕴含或完全识别错误日期解释。错误适用范围、遗漏替代关系等仍需实际案例和人工核验。对话历史按 user/assistant 角色传给模型以帮助恢复指代，系统指令仍要求重新读取制度原文。

## 故障、预算与超时

工具失败是结构化观察，模型可以再次行动；空命中为 `ok=true/hits=[]`。格式错误消耗模型额度并反馈修正，实际工具失败消耗工具额度。无隐藏网络重试。

工具上限用尽后允许剩余模型调用提交结果；额外工具行动被拒绝并返回 `incomplete/budget_exhausted`。预算耗尽仍没有合法结果也返回该状态。工具错误阻断时模型可返回 `tool_failure`；模型连接或适配器异常由执行器返回 `model_failure`。

单次调用采用有界等待；HTTP 请求同时设置 socket 超时，本地检索检查截止时间。线程超时后结果被丢弃，不能登记证据或追加行动；后台只读工作可能短暂继续，无法保证取消供应商已经开始的生成或计费。该实现适用于当前 CLI 的只读工具，不是生产级强制进程隔离运行时。

Trace 记录简短行动目的、参数、完整观察及摘要，不请求/记录模型内部思维。HTTP 错误不回显供应商响应体或凭据。写入失败通过运行层错误和非零退出码报告，不能宣称证据已保存。
