# 合成知识库

所有企业、产品及条款均为虚构测试材料，不代表小影或其他真实企业制度。本文是开发说明，不作为模型检索材料。

## 加载边界

每个 `corpora/*.json` 文件是完整、可独立加载的文档数组。一次运行只能选择一个快照，禁止递归加载整个 `data/` 目录或混合多个快照。数组元素遵循接口契约的文档结构。业务工具只检索、读取所选快照；文件名、本文和测试断言不是业务证据，不传给模型。

| 快照 | 文档 | 目的 |
|---|---|---|
| `normal.json` | D01、D03、D04、D05 | 正常回答、相似问法、上下文、资料外问题、产品 FAQ |
| `conflict.json` | 正常集加 D02 | 30 天与 15 天冲突；D02 较新但没有替代依据 |
| `resolved.json` | 冲突集加 D06 | 对明确适用日期的行程消解冲突 |
| `changed.json` | 正常集，仅 D01 原文 30 天改为 45 天 | 检查答案依赖原文及索引刷新，文档 ID 和日期故意保持不变 |
| `scoped.json` | 冲突集，D01/D02 分别限定总部/海外分支机构 | 区分条件差异和规则矛盾；用户范围未知时追问 |

同一快照内 ID 唯一，不同快照允许同 ID 表示测试变体。共享内容有意复制，使快照独立加载；数据完整性测试检查共享文档是否意外漂移。最终运行的 `corpus_revision` 应对内容计算摘要，不能仅使用文件名、日期或文档 ID。

## 条款设计

- D01/D02 的起算点均为行程结束，数值不同；未标注适用范围、优先级或替代关系。
- D03 提供报销材料及缺失材料的处理方向，不提供另一套期限。
- D04 提供出差审批与变更流程，作为相关但不能支持期限答案的资料。
- D05 限定星帧剪辑 2.0 桌面版，不能据此推断移动端或其他版本。字幕可导出 SRT/TXT。
- D06 明确从 2026-04-01 起适用，以行程结束日期判断；只替代 D01/D02 的期限条款。B03 输入提供 2026-05-10 的行程结束日期。缺少日期或日期早于适用范围时不能自动消解冲突。
- 第四阶段为 D06 加入文档级 `citation_dependencies: {"P01":["P02"]}`，声明期限与替代依据必须配套引用。它是可审查的原文关系，不是问题到答案的映射；没有改动期限、日期或制度正文。模型仍需根据读取结果选择下一工具并逐字引用两段原文。
- 未提供育儿假、购房补贴或报销逾期后果，模型不能凭常识补充。

片段包含完整句子和必要限定条件，没有预设模型行动、期望状态或案例标签。D06 使用多个片段，要求回答者同时核实期限与替代关系。检索和读取已实现；第四阶段 B03 两次真实运行均引用期限与替代原文，B04 两次均追问范围。这些有限案例不证明对所有文档条件都能正确应用，见 [第四阶段报告](../docs/10-reliability.md)。

第四阶段检索还过滤“规定、制度、公司”等泛词，并移除将“多少天”直接等同“截止期限”的归一化，避免育儿假等资料外问题仅靠泛词命中报销制度。该过滤不意味着已经覆盖所有陌生表达。

## 案例与数据验证

`tests/fixtures/inputs/` 保存请求示例，`tests/fixtures/case-manifest.json` 保存测试侧快照映射、预期状态与故障注入配置。预期内容必须留在评估器侧；故障注入已接入执行器。离线脚本在 `tests/fixtures/mock/`，不是业务知识，不进入检索索引。

第五阶段输入增至18组，包括同问题冲突、历史错误答案、多对象指代与生效日期边界。资料仍为原有5个独立快照；实际输出及未通过项见 [效果验证报告](../docs/11-effect-evaluation.md)，不能把请求样例当作运行结果。

在仓库根目录运行（Python 3.9+，仅标准库）：

```text
python -m unittest discover -s tests -p "test_knowledge_data.py" -v
```

该命令只验证数据结构、隔离和关键条款设计，不执行模型，不证明检索质量或 Agent 验收通过。实际数据检查报告保存于 `examples/data-validation/`，与未来 Agent Trace 分开。
